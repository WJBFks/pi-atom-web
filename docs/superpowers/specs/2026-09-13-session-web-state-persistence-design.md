# 会话 Web 派生状态持久化设计

## 目标

将 Pi 会话文件没有记录、但 pi-atom-web 需要跨 `/reload` 和进程重启恢复的数据保存在工作区的 `.pi/atom/<sessionId>/web-state.json`。全局同类设置预留在 `~/.pi/atom/`，本阶段不创建全局文件。

## 数据边界

项目级文件保存格式版本、Thinking 最终耗时、工具最终耗时、Thinking/工具卡片的用户折叠状态，以及命令和通知镜像记录。运行中的工具、临时 Prompt、SSE 客户端、连接凭证、计时器、弹层和滚动位置不落盘。

文件中的实体使用会话、branch entry、toolCallId 等稳定标识。读取后只向当前会话恢复；无法解析、版本不支持或字段无效的文件按空状态处理。数量和文本长度保持既有上限。

## 写入和恢复

扩展在会话启动或切换时异步读取当前工作区和会话对应文件。状态变化后通过短防抖合并写入，先写同目录临时文件再原子替换目标文件。会话切换、关闭和 `/reload` 前刷新待写内容。目录仅在首次实际写入时创建。

浏览器通过受现有 token、Origin 和 sessionId 校验保护的 action 上报 Thinking/工具卡片状态及 Thinking 最终耗时。服务端进行结构、长度和数量校验后合并并持久化，再随 Snapshot/patch 下发。

## 验证

单元测试覆盖路径隔离、原子写入、合并、防抖刷新、损坏文件和版本降级。协议测试覆盖 UI 状态 action。桥接测试覆盖工具耗时和显示记录在重载后恢复。执行 `npm run check`、`npm test` 和 `npm run test:browser`。
