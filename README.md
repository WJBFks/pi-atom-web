# pi-atom-web

## 项目级 Codex Skills

项目在 `.agents/skills/` 内提供 10 个 Codex 技能：`pi-vue-nobuild`、`frontend-design`、`vue-best-practices`、`pinia`、`vue-router-best-practices`、`node`、`web-design-guidelines`、`accessibility-compliance`、`responsive-design`、`interaction-design`。它们只作用于本项目；重新打开任务后由 Codex 自动发现。`pi-vue-nobuild` 固定浏览器原生 ESM、Vue 3、Pinia、Vue Router 与无前端构建步骤的架构，优先于通用技能中的冲突建议。

pi-atom 系列的独立产品：在运行中的 pi TUI 输入 `/web`，打开当前会话的浏览器界面。网页与终端共享同一个 pi 进程、模型、上下文和对话；TUI 切换当前会话时网页跟随切换。

界面布局参考 [pi-atom-console](https://github.com/WJBFks/pi-atom-console)，保留居中对话、浅色面板和工具折叠的视觉方向。本产品聚焦当前会话的使用与展示，不提供项目管理、会话管理或独立 agent 后端。

页面统一使用字体栈：`Noto Sans Mono`、`JetBrains Mono`、`Fira Code`、`Consolas`、`ui-monospace`、`Microsoft YaHei`、`monospace`，按顺序回退。Noto Sans Mono 以本地可变 WOFF2 资源随扩展提供，不依赖系统字体或外部 CDN。

## 使用

要求：Node.js 22.18 或更高版本；支持 `ExtensionContext.mode`、消息事件及 `sendUserMessage` 的 pi 版本。

将本目录放在 `~/.pi/agent/extensions/pi-atom-web/`，在此目录执行：

```bash
npm ci
```

更新扩展后必须在已运行的 pi 中执行 `/reload`，再执行 `/web` 打开新地址。仅刷新网页会读取新的静态文件，但不会更新 pi 内存中的扩展逻辑；页面检测到旧后端缺少命令列表时会提示重新加载。SSE 快照和增量按实际 JSON 传输结果校验，Pi 内存对象中的未定义可选字段不会阻止 Web 建立连接；后端协议使用可重载的 TypeScript 入口，新增协议字段会随扩展一起生效。

命令：

```text
/web
/web stop
```

`/web` 启动本机随机端口服务并打开浏览器，再次执行会复用服务。浏览器无法自动启动时，复制 TUI 显示的完整地址。`/web stop` 关闭网页服务；pi 退出或 reload 时也会关闭。

Web UI 中可直接输入 `/reload`。请求经内部扩展命令取得 pi 的命令上下文并调用宿主 TUI 原生重载流程，随后以原端口和凭证恢复 `/web`；当前标签页自动重连，并在确认连接到新的扩展实例后自动刷新浏览器一次，不需要重新打开地址。生成期间不能重载。

## 功能

- 当前分支的用户消息、助手回答、Markdown、思考过程和工具结果；用户及命令消息使用右对齐、内容自适应宽度的气泡布局，用户气泡与助手消息都不显示角色标签。Markdown 围栏代码块提供本地 highlight.js 语法高亮、语言、总行数、逐行行号和复制按钮，长行不折行并可横向滚动。思考块使用页面背景和加粗 `Thinking` 前缀；折叠时压缩全部空白并按页面实际宽度显示一行，仅溢出时追加 `...`，展开后按原格式显示完整内容。思考进行时默认展开并实时计时，完成后默认折叠；思考计时在思考结束时立即停止，同一轮内思考块之后出现正文或工具调用即视为结束，不把后续输出计入耗时，只有位于消息末尾、仍在生成的思考块继续计时到整轮结束；若用户在进行中手动操作过，则完成后保留其选择。折叠耗时精确到秒且不足一秒显示 `<1s`，展开增加毫秒，时间在标题行内垂直居中。工具调用按 `toolCallId` 将输入与输出合并为一张可折叠卡片，使用与 Thinking 相同的原生折叠箭头，标题以状态色显示加粗工具名和关键参数（如 **bash** `echo "thinking..."`），展开后以统一外框分隔 Input/Output；Input 使用 JSON 代码块，运行中、成功和失败使用不同状态色，运行时间在标题行内垂直居中，全部内容继承项目默认字体。读取 `SKILL.md` 的 `read` 调用单独展示为紫色技能卡：折叠标题是 `skill` 加技能名（如 `skill pi-vue-nobuild`），与普通 `read` 一眼区分。
- 实时生成内容与工具执行状态；工具块右侧实时显示执行耗时，折叠时精确到秒且不足一秒显示 `<1s`，展开时精确到毫秒，完成后固定最终耗时；执行轨迹视图。历史消息与实时区域独立更新，流式输出不会重建整段历史 DOM。每一轮从用户输入到最终输出之间的中间过程（思考、工具调用、中间正文）收进一个折叠块，标题形如 `2 次思考过程 · 3 次工具调用 · 1 条消息`（为 0 的分段不显示，没有中间过程则不显示标题），最终输出留在折叠块之外；仍在生成的一轮默认展开，中间过程结束后自动折叠，可手动展开。
- Web 提交普通 prompt 时会先在浏览器同一交互帧显示用户消息卡；后端临时消息或真实会话记录到达后自动替换且不重复，明确发送失败时撤销。提示词模板与技能命令也会跟踪各自的模型轮次。模型超过 1 秒尚未开始响应时显示 `正在等待模型响应... (Ns)`，收到首个响应事件、轮次失败或取消后立即移除。
- 输入框左下角可选择图片，也可把图片拖入浏览器或直接粘贴到输入框；提交前显示可预览、可移除的方形缩略图，允许只发送图片或与文字组成同一条消息。发送后，多张图片以 80px 方形附件条右对齐显示在用户文字气泡上方。输入框附件和会话图片均可点击打开全屏等比例预览，并支持关闭按钮、点击遮罩或 `Esc` 关闭。支持 PNG、JPEG、GIF、WebP，最多 4 张，单张不超过 8 MiB、合计不超过 16 MiB。
- 网页发送的斜杠命令显示为命令记录；服务运行及 `/reload` 替换实例初始化期间的 `ctx.ui.notify()` 同步为 TUI 通知（如 `/wj-status`），保留终端输出。展示记录按会话与分支隔离，项目级保留最近 500 条且不进入模型上下文；只有包含随机凭证的 Web 连接地址不会镜像。
- 所有插件通过 `pi.appendEntry(customType, data)` 写入的自定义会话 Entry 都会转发到 Web，无需为插件逐个适配。后端调用 Pi 当前注册的 TUI renderer 生成折叠态和展开态文本并清除 ANSI 控制码；Web 通用卡片优先显示该文本，展开正文使用与 TUI 通知相同的默认字体，原始 JSON 收在“原始数据”二级折叠区。renderer 不存在或执行失败时，可识别的对象数据按 JSON 代码块展示并以 `[JSON OBJECT]` 作为摘要，其他值按纯文本展示；TUI 组件本身不会在浏览器执行。
- Thinking、工具调用、TUI 通知和自定义 Entry 共用统一的折叠卡片基座。所有折叠摘要把连续空白和换行压成单个空格，只显示一行并在溢出时显示省略号；通知与自定义 Entry 默认折叠，展开后显示完整通知正文或结构化数据。
- 发送消息默认使用追加（followUp）模式；composer 使用顶部略宽、其余方向紧凑的 padding，prompt 不叠加上下 padding，默认显示 2 行并自动增高至最多 10 行且不超过会话区可用高度，操作栏高度与 32px 圆形发送按钮匹配。发送 SVG 精确居中，hover/active 保持强调色；支持停止当前生成。输入框右侧以无图标文本按钮打开模型选择器，按供应方筛选真实可用模型并搜索；相邻按钮独立选择思考级别，并只列出当前模型实际支持的级别。当前模型、供应方和思考等级会默认选中；供应方筛选切换后保持当前选择，“显示全部”按供应方名称分组模型，右侧标题和搜索框固定、仅下方模型列表滚动；无当前模型时，单一供应方自动选中，多个供应方保持显示全部。底部 Token 输入/输出使用尺寸与形状完全对称的 SVG 箭头。
- 输入 `/` 提示当前 pi 的扩展命令、提示词模板、`/skill:…` 与 Web 命令；按前缀筛选，↑/↓ 选择，Tab/Enter 或点击补全，添加参数后发送；Esc 关闭提示。Web 支持 `/reload`、`/model`、`/session`、`/copy`、`/name <名称>` 和 `/compact [指令]`；其余已知命令通过 pi 原生命令分发与模板展开执行。
- 当前会话名称、目录、模型与思考等级；未设置标题时显示“未命名会话”；明暗主题；自动重连。浮动输入框右侧以 `模型 · 思考等级` 展示当前状态；输入区、状态栏和信息卡统一使用内联 SVG 图标。下方状态栏由 `.status-shell` 提供稍宽松且上下相等的间距，按钮、文字与 SVG 使用统一行盒并完整垂直居中，汇总会话标题、对话/轨迹、估算输出速度、Token、缓存命中率与成本，只更新数值文本而不重建按钮，保证 hover 稳定；点击会话标题展示会话 ID、会话文件路径、所属工作区及路径、活跃与创建时间、活跃时长，其他分组也可查看并复制详细值。左下角提供相同的会话信息卡。信息卡点击触发按钮或卡片以外的任意位置关闭。
- TUI 切换会话后同步网页，并拒绝携带旧会话 ID 的操作；未发送草稿按会话保留在页面内存。

## 边界

这是结构化会话界面，不是终端画面的镜像。尚未适配的内置终端命令（如 `/settings`）、自定义 TUI widget 仍在终端使用；扩展交互请求见下方通用支持说明；图片目前显示占位提示。网页发送使用 pi 的用户消息 API；仅对当前命令列表中的斜杠命令启用命令分发，未知命令报错，不作为普通消息交给模型。命令接收成功表示已交给 pi，通过 `notify` 输出的命令结果会同步网页；其他错误展示方式仍在 TUI 显示，标准交互弹窗通过扩展请求桥接。网页不直接执行终端 shell 命令。已有生成在扩展首次加载之前开始时，网页会在后续消息事件或完成后更新。

服务只监听 `127.0.0.1`，每次启动生成随机凭证。凭证由 URL fragment 传入并存入当前标签页的 sessionStorage，API 校验凭证、Host 和 Origin。网页不加载远程脚本，Markdown 经 DOMPurify 清洗，远程图片不自动加载。完整打开链接相当于当前会话的操作凭证。

Pi 会话文件未记录的 Web 派生状态保存在当前工作区 `.pi/atom/<sessionId>/web-state.json`：Thinking 与工具的最终耗时、用户手动折叠状态，以及 Web 镜像的命令和通知。文件采用版本化 JSON 和同目录原子替换，损坏或版本不支持时安全回退为空状态。随机连接凭证、临时 Prompt、运行中的工具和界面滚动位置不会写盘。跨项目设置统一预留在 `~/.pi/atom/`；当前没有需要写入的全局 Atom 设置，因此不会创建该目录。

不创建额外 pi 进程，不直接读写会话文件，不生成运行时数据文件，也不修改全局配置。主题偏好仅保存在浏览器中。

## 开发验证

前端使用 Vue 3 Composition API 的普通 JavaScript `h()` 组件、Pinia 和 Vue Router memory history。浏览器直接加载本地 ESM，不需要构建或模板编译；Vue runtime、Pinia、Router 及 devtools API 均通过 HTTP 白名单提供。固定 import map 使用 CSP SHA-256 校验，不开放外部 CDN、`unsafe-inline` 或 `unsafe-eval`。

`shared/protocol.js` 由扩展与浏览器共同使用，校验版本、动作和事件结构。SSE 首次连接发送快照，后续按字段发送增量并附带流标识、序号和会话 ID；实时消息更新不携带完整历史。工具运行事件经 `extensions/tool-events.ts` 转为有界、可序列化的数据，工具私有对象不会破坏事件流；无法编码的单条事件会被跳过且不消耗 SSE 序号。浏览器将历史列表和实时列表分为独立组件，按稳定消息 ID 保持节点与 Thinking 手动状态。断线、卸载和重载会取消连接、请求及重试任务。

```bash
npm run check
npm test
npm run test:browser
```

`check` 递归检查扩展、共享协议和所有浏览器模块；`test` 在没有测试文件时失败。浏览器测试独立运行，通过内存快照和模拟动作驱动真实本地 HTTP 服务，不调用模型、不读写真实会话。当前 Windows 默认使用已安装的 Microsoft Edge；其他系统可设置 `PLAYWRIGHT_CHANNEL=chromium` 并先执行 `npx playwright install chromium`。

`extensions/index.ts` 负责 pi 生命周期和会话桥接；`extensions/server.ts` 提供 HTTP/SSE；`web/main.js` 启动应用，`web/api/` 管理传输，`web/stores/` 管理状态，`web/components/` 与 `web/views/` 负责 UI。Marked、DOMPurify、highlight.js 与 xterm.js 均通过本地 HTTP 路径提供，正常使用无需 CDN。

### 重载与入口缓存

扩展使用 `.ts` 入口和服务模块，避免当前 pi 加载器对原生 ESM `.js` 的缓存导致 `/reload` 后继续运行旧代码。由旧版升级后执行 `/reload` 再 `/web`，扩展清单会加载新的 `.ts` 路径。

## 通用扩展请求

按 pi UI 接口统一桥接，无需为 `/piolium-help` 等命令编写专用适配：

- `select`、`confirm`、`input`：网页显示选择、确认或输入控件，支持取消；网页与 TUI 任意一端完成后关闭请求，返回原始选项值。
- `custom`：使用本地 xterm.js 镜像同一个 TUI 组件的渲染行，保留 ANSI SGR 颜色、背景与选中样式；按终端列宽等比缩放到网页面板，避免横线折行。点击面板后直接输入，支持方向键、Tab、退格、Ctrl/Alt 组合键、中文与粘贴；按顺序转发输入并在更新后保留焦点。不创建第二个组件实例，像素图片/终端私有图形协议不转换。
- `editor`：显示标题和预填内容，提示在 TUI 完成。当前宿主接口不支持外部提交/取消，不能安全地从 Web 接管。
- 请求以 ID 和会话 ID 校验，重连时重发仍在等待的请求；收起保留等待，取消才结束请求。服务停止恢复原 UI 方法。

设计参考 [pi-atom-console 的扩展 UI 通道](https://github.com/WJBFks/pi-atom-console/blob/main/lib/rpc-manager.ts)，但本扩展保留并桥接宿主 TUI。

输入框作为 dock 浮动固定在对话区底部，问卷与通用扩展请求固定显示在输入框正上方，三者与对话同宽。页面不显示产品顶部标题栏和左侧会话栏，对话区占满整个视口；对话工具栏保持固定，其下方消息区使用完整高度纵向滚动条。只有消息区位于最底部时才自动跟随新内容，用户向上滚动任意距离后立即暂停，重新滚到底部后恢复；离底时在输入框上方居中显示圆形向下按钮，点击即可回到最新消息。对话消息、输入框与底部状态栏共用同一条居中列，默认 860px；鼠标移到内容区左右边界时会在鼠标高度出现一条两端渐隐的细线手柄，拖动可对称调整这条列的宽度，双击手柄恢复默认，键盘聚焦后也可用 ←/→ 调整，宽度记在浏览器本地，窄视口不提供。页面按 dock 实际高度为消息增加底部留白，使最后一条消息可以滚动到浮层上方。长问卷仅滚动卡片内容区，长通用扩展请求滚动请求面板，输入框始终可见。会话详情、工作区、模型、思考等级和统计仍可从底部状态栏查看。

跳到最新消息时会先恢复自动跟随，并在当前界面更新和下一渲染帧再次校准到底部；快速增长的 Thinking 或工具输出不会超过这次跳转。

终端画面仅允许 SGR 样式控制，屏蔽 OSC 链接、剪贴板命令及其他终端控制。面板仍只有外层滚动条；TUI 很宽时等比缩放会使文字变小，可缩窄原终端改善阅读。

## ask_user_question 专用适配

已检查并实测本机 `@juicesharp/rpiv-ask-user-question` **2.6.2** 的参数、事件和结果协议。该工具始终优先使用结构化问卷，不再解析终端画面或模拟方向键来填写。

| 原扩展能力                  | Web 表现与返回语义                                                                                                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1–4 个问题，每题 2–4 个选项 | 顶栏显示原始 question.header（单题同样保留），并提供分页、上一题/下一题和核对页；保留 question/label/description                                                                          |
| 单选                        | 原生 radio；返回 `kind: option` 和选项原始 label                                                                                                                                          |
| 多选                        | 原生 checkbox；普通选项和自由回答可以同时选择，返回 `kind: multi`，selected 先按原选项顺序排列，再附加非空自由文本                                                                        |
| 自由填写（所有题型）        | 多行文本框；单选题返回 `kind: custom` 并替代普通选项；多选题作为额外 selected 项，不清除普通选项；单选空文本按原协议返回 null                                                             |
| 备注                        | 每题独立多行备注，附在对应答案的 notes；备注不把未答题变成已答                                                                                                                            |
| 单选 preview                | 选择区与预览区共用统一外框；使用紧贴选项的低高度折叠条，展开后安全渲染 Markdown/代码，支持逐项对比；表单重绘保留每项展开状态；选中后原始 preview 随答案返回；多选与自由回答不携带 preview |
| 多题核对与修改              | 核对页列出答案、备注、未答项，可返回修改；允许显式提交部分答案；全未答由原工具按其既有逻辑判为未回答                                                                                      |
| 取消                        | 返回 `{answers, cancelled:true}`，保留已填的有效部分；不返回 undefined，以免误触发原工具的 RPC 降级逻辑                                                                                   |
| 收起/恢复                   | 收起只隐藏表单，不提交或取消；草稿保留                                                                                                                                                    |
| 刷新/重连                   | 同一请求在本标签页 sessionStorage 恢复草稿；请求结束后清理，新请求独立                                                                                                                    |
| TUI 作答                    | TUI 仍可完成问卷；任意一端最终提交/取消后，另一端的请求关闭，迟到回应被拒绝                                                                                                               |

网页与 TUI 的**未提交草稿独立**，不会逐键同步；最终先完成的一端生效。浏览器使用多行文本框完成编辑，TUI 的 Ctrl+G 外部编辑器与终端快捷键配置仍由原扩展负责。多语言题目原文保留，网页控件使用中文。

实现：`extensions/ask-user.ts` 关联真实工具调用参数（含 preview）与公开 `rpiv:ask-user:prompt` 事件，再匹配当前版本的 QuestionnaireSession 工厂；`dialogs.ts` 把经过校验的 QuestionnaireResult 交给原 done 回调，原工具继续生成其标准返回文本、details 和完成事件。`web/components/dialogs/AskUserForm.js` 提供 Vue 表单和草稿管理。无需修改或打补丁到被适配扩展。

必须先启动 `/web` 再触发新问卷；已打开的旧 TUI 问卷不会被事后接管。若未来扩展更改工厂/协议而未匹配，保留原 custom 兜底，不把其他扩展的请求错认成问卷。

专用问卷采用紧凑独立卡片，普通选项纵向排列；自由回答作为最后一张同款选项卡，仅显示随题型变化的选择框和带 placeholder 的输入框：单选题使用 radio，聚焦或输入会选中自由回答并取消普通选项；多选题使用 checkbox，聚焦或输入只勾选自由回答，可与普通选项并存。备注仍按需展开，说明同样使用 placeholder。“清除选择”和“取消问卷”集中在底部操作栏，与导航和提交按钮排列在一起。单题作答后可直接提交，多题保留核对页；问卷固定在输入框上方并随内容增高，达到可用高度后仅滚动问卷内容区。选项、页签和表单按钮引起局部重绘时保留当前滚动位置。
