## 项目级 Codex Skills

项目在 `.agents/skills/` 内提供 11 个 Codex 技能：`pi-vue-nobuild`、`pi-package-compatibility`、`frontend-design`、`vue-best-practices`、`pinia`、`vue-router-best-practices`、`node`、`web-design-guidelines`、`accessibility-compliance`、`responsive-design`、`interaction-design`。它们只作用于本项目；重新打开任务后由 Codex 自动发现。`pi-vue-nobuild` 固定浏览器原生 ESM、Vue 3、Pinia、Vue Router 与无前端构建步骤的架构；`pi-package-compatibility` 规定 Pi 第三方 package 的双端目录、按需激活、静默缺失、通用桥接和验证原则。

pi-atom 系列的独立产品：在运行中的 pi TUI 输入 `/web`，打开当前会话的浏览器界面。网页与终端共享同一个 pi 进程、模型、上下文和对话；TUI 切换当前会话时网页跟随切换。

界面布局参考 [pi-atom-console](https://github.com/WJBFks/pi-atom-console)，保留居中对话、浅色面板和工具折叠的视觉方向。本产品聚焦当前会话的使用与展示，不提供项目管理、会话管理或独立 agent 后端。

页面统一使用字体栈：`Noto Sans Mono`、`JetBrains Mono`、`Fira Code`、`Consolas`、`ui-monospace`、`Microsoft YaHei`、`monospace`，按顺序回退。Noto Sans Mono 以本地可变 WOFF2 资源随扩展提供，不依赖系统字体或外部 CDN。

## 使用

> 面向 agent 的完整安装手册（依赖为什么必须装、运行期文件落在哪、故障排查）见 [`INSTALL.md`](INSTALL.md)。

要求：Node.js 22.18 或更高版本；支持 `ExtensionContext.mode`、消息事件及 `sendUserMessage` 的 pi 版本。

将本目录放在 `~/.pi/agent/extensions/pi-atom-web/`，在此目录执行：

```bash
npm ci
```

更新扩展后必须在已运行的 pi 中执行 `/reload`，再执行 `/web` 打开新地址。仅刷新网页会读取新的静态文件，但不会更新 pi 内存中的扩展逻辑；页面检测到旧后端缺少命令列表时会提示重新加载。SSE 快照和增量按实际 JSON 传输结果校验，Pi 内存对象中的未定义可选字段不会阻止 Web 建立连接；后端协议使用可重载的 TypeScript 入口，新增协议字段会随扩展一起生效。
长会话的首屏只包含最近 10 轮并把中间过程全部折叠。提交新 prompt 和模型流式输出期间仍只同步这个窗口，不会把完整历史重新发到浏览器。用户滚动到消息区顶部时才向前加载 5 轮更早历史，插入后保持原来的可见位置；页面不会在后台连续补齐全部历史而占用主线程。

命令：

```text
/web
/web-wlan
/web stop
```

`/web` 打开本机 Web UI 并自动弹浏览器，再次执行会复用服务。地址是**固定端口 + 会话路径**：`http://127.0.0.1:31359/<会话短码>/#<凭证>`，短码由会话 ID 稳定派生（同一个会话重开或 `/reload` 都不变，地址可以收藏；凭证默认每次随机，要长期收藏就在「设置 → 会话 → Web 服务」打开「固定凭证」）。多个 pi 进程各开一个 `/web` 时共用这一个端口、按路径区分，**彼此互不影响**：任何一个会话退出都不会把其它会话的页面弄挂。`/web stop` 只关本会话的服务与它的路由登记（网关进程在所有会话都离开后自行退出）。浏览器无法自动启动时，复制 TUI 显示的完整地址。

**上次显式开过 Web 的会话，重启 pi 后会自己把服务开回来**（用户 2026-09-30：页面常常开在另一台机器上，那边的人回不到 TUI 执行 `/web`）：短码与固定凭证都只跟会话 id 有关，所以收藏的地址直接又能打开。登记表在 `~/.pi/atom/web/sessions.json`，只有 `/web`、`/web-wlan` 会写它，`/web stop` 会抹掉（“用户主动关了”就是不再自动开的意图）；总开关是「设置 → 会话 → Web 服务 → 自动恢复」，或 TUI 里 `/web auto on | off | status`。前提：要真的能收藏地址请开着「固定凭证」，否则重启后凭证重新随机，页面会拿旧 token 吃 401。新建会话（`/session`）的短码与凭证都会变，这一步救不了。

打开一个**短码已不在路由表里**的地址（会话退出、pi 正在重启、心跳还没续上）时，浏览器看到的不再是一排 404：网关对文档请求返回一个「会话不在线」页，**每 3 秒自动重试、最长 3 分钟**，接回来就自己跳进去（页面里没有脚本，重试用 `<meta http-equiv="refresh">`；超时后停下来给结论，不会永远转圈）；API、SSE 与静态资源仍旧是 404 JSON。

地址里少了个结尾斜杠、或者从别处抄回了不带前缀的地址，也不会再整排红：走网关时服务端会给页面注一个 `<base href="/<会话短码>/">`（网关把前缀用 `x-forwarded-prefix` 递进来），整页的相对引用与接口从此以 `/<短码>/` 为基准，**与文档 URL 长什么样无关**（`web/api/base.js` 的 `apiPath()` 改成优先读这个 `<base>`）。

`/web-wlan` 让服务监听 `0.0.0.0`，局域网内其它设备用 `http://<网卡地址>:31360/<会话短码>/#<凭证>` 打开同一会话（与本机模式是两个端口，不共用一个，否则两种模式会抢端口而串台）；已有服务时会就地重绑并复用凭证（已打开的页面不失效）。TUI 会把每张网卡都列成**带凭证的完整地址**，直接整条复制即可——凭证在 `#` 片段里，只输 `IP:端口` 会提示缺少连接凭证。该模式目前**不校验 Host/Origin**，请仅在可信网络使用；安全加固列在文末「待办」。

Web UI 中可直接输入 `/reload`。请求经内部扩展命令取得 pi 的命令上下文并调用宿主 TUI 原生重载流程，随后以原端口和凭证恢复 `/web`；当前标签页自动重连，并在确认连接到新的扩展实例后自动刷新浏览器一次，不需要重新打开地址。生成期间不能重载。

## 功能

- 顶部是页面 tab：**当前只展示「对话」与「设置」**，标题行左侧显示会话名与重命名按钮（Enter 提交、Escape 取消，复用 `/name` 命令），右侧显示同步状态；←/→/Home/End 在 tab 间切换。**轨迹**（将改为独立页面）与**上下文**页暂时收起入口，视图代码保留，见文末「待办」。对话与轨迹共用消息区（轨迹不做按轮折叠），上下文页汇总上下文构成、Token 用量、缓存与成本，并列出分支摘要与上下文压缩摘要。切换 tab 不重建消息区，也不会丢失滚动位置；上下文与设置页不显示输入框（连同状态栏），把底部空间让给页面内容。
- 设置页是左侧分类导航（每项左侧各带一个图标；手机窄屏只显图标、不显文字）+ 右侧内容：一级只有**常规、会话、定义、关于**四项（用户 2026-09-25 选定）——前三个分类各自在内容顶部用一条横向 tab 分开：常规 = 外观 / 行为，会话 = 会话信息 / 连接与实例，定义 = 技能 / 扩展 / 模板 / 其他（原「定义」）；「关于」没有二级，直接列版本与协议（扩展版本 / 协议 schemaVersion / 实例 ID / 服务地址）、运行环境（浏览器与系统从 UA 解析、语言、视口与像素比、内容列可用宽度、安全上下文、访问方式）与使用说明，窄视口下一级导航折叠为横向排列。外观包含主题（浅色 / 深色 / 跟随系统）、内容列宽度与安全区（顶部 / 底部 px，避开手机刘海、状态栏与浏览器工具栏的遮挡）——两者都是「数值输入 + 滑块」调整，最右侧图标一键还原默认值，且**只要停在设置页，上下安全区就会被涂成中性灰并在中间标注 `(顶部安全区)` / `(底部安全区)`**（离开设置页恢复正常，值为 0 时不显示）；手机上软键盘弹出期间底部安全区会自动让位，不会把输入框顶得更高；连接与实例（「会话」的第二个 tab）展示当前地址、实例 ID、连接状态、凭证是否已保存（不回显凭证本身）；行为包含自动折叠中间过程与自动跟随新消息（「默认视图」待轨迹与上下文页接回后重新提供）；偏好保存在浏览器 `localStorage`。技能/扩展/模板/其他四个 tab 是只读的「Agent 定义」展示：列出 pi 实际加载的技能、扩展与 Prompt 模板（带全局/项目/包来源标记），以及上下文文件、SYSTEM/APPEND_SYSTEM 提示词文件、settings.json、packages 声明与项目信任状态；不展示主题（PI 的 TUI 主题与 Web UI 不兼容）。窄视口下分类导航折叠为横向排列。

- 当前分支的用户消息、助手回答、Markdown、思考过程和工具结果；用户及命令消息使用右对齐、内容自适应宽度的气泡布局，用户气泡与助手消息都不显示角色标签。Markdown 围栏代码块提供本地 highlight.js 语法高亮、语言、总行数、逐行行号和复制按钮，长行不折行并可横向滚动。思考块使用页面背景和加粗 `Thinking` 前缀（耗时由后端从事件流计时并落盘，**Web 未启动或标签页在后台也不丢**，正在生成的那一块也能实时看到秒数）；折叠时压缩全部空白并按页面实际宽度显示一行，仅溢出时追加 `...`，展开后按原格式显示完整内容。**所有思考块默认折叠（包括正在生成的那一个）**，耗时照常统计与显示，要看全文自己点开；思考计时在思考结束时立即停止，同一轮内思考块之后出现正文或工具调用即视为结束，不把后续输出计入耗时，只有位于消息末尾、仍在生成的思考块继续计时到整轮结束；若用户在进行中手动操作过，则完成后保留其选择。折叠耗时精确到秒且不足一秒显示 `<1s`，展开增加毫秒，时间在标题行内垂直居中。工具调用按 `toolCallId` 将输入与输出合并为一张可折叠卡片，使用与 Thinking 相同的原生折叠箭头，标题以加粗工具名和关键参数显示（如 **bash** `echo "thinking..."`），展开后以统一外框分隔 Input/Output；Input 使用 JSON 代码块，折叠块只有三种状态：正常灰、警告橙、报错红——工具报错时整行（图标、标题与单行摘要）标红，运行中与成功都是正常灰；**折叠态的摘要就是工具输出**（工具卡没有另设摘要，报错时那段输出本身就是报错信息）：连续空格算一个空格、换行也算一个空格，只占一行，超出显示省略号（最长先截到 300 字）；没有输出时不摆摘要与分隔点；**read/write/edit 的专用状态行会跟着变**：「正在读取 / 成功读取」在失败时写成「读取失败」并转红，完整报错放在状态行下方的报错块里（状态行右侧不摆报错摘要，不与下方重复），失败时不再显示 `+N -M` 这类变更统计；运行时间在标题行内垂直居中，全部内容继承项目默认字体。读取 `SKILL.md` 的 `read` 调用按技能卡展示：折叠标题是 `skill` 加技能名（如 `skill pi-vue-nobuild`），配色与普通折叠块一致（正常灰）。`write` 与 `edit` 作为 pi 系统工具有专门视图：`write` 直接展示高亮的写入内容（含语言、行数与复制按钮），`edit` 展示 `-`/`+` 变更（带文件行号、整块横向滚动且行号固定；结果未回来时按参数回退、不编造行号），**行内还有词级高亮**：同一行的旧/新内容会再算一次 token 级 diff，只圈出真正改掉的字段（比如只改了 `usage.output` → `averageSpeed(session)` 时，同一行其余部分不上色），行首缩进不算改动，删/增行数不等时不猜对应关系；`read` 的结果按路径语言高亮（行号从 `offset` 开始），`bash` 的输出作为终端原文展示（不套 markdown）；`grep`/`find`/`ls` 的结果也作为逐行原文（不套 markdown，路径里的 `_`、`*` 不会被改写），标题取模式/路径；这些工具 INPUT 都是专门视图（read 参数行、bash 命令代码块），原始 JSON 收进「原始 Input」折叠；工具自己的截断/继续提示语放在代码块之外，两者的原始入参收在「原始 Input」二级折叠里。
- 实时生成内容与工具执行状态；工具块右侧实时显示执行耗时，折叠时精确到秒且不足一秒显示 `<1s`，展开时精确到毫秒，完成后固定最终耗时；执行轨迹视图。已结束的轮次与进行中的那一轮分别更新，流式输出不会重建整段历史 DOM。每一轮从用户输入到最终输出之间的中间过程（思考、工具调用、中间正文，以及**以引导方式插入的用户消息**与**自动压缩条目**）收进一个折叠块，标题形如 思考`2` · 工具调用`3` · 消息`1` · 引导`1` · 压缩`1`（前四段是「这一轮做了什么」，按流程顺序；「引导」是本轮被插话的次数、「压缩」是被**自动**压缩的次数，作为本轮元信息排在流程之后，压缩固定垫底；数量为行内代码样式的徽片；为 0 的分段不显示，没有中间过程则不显示标题），最终输出留在折叠块之外；**轮次分组内部还有一层「中间过程组」**（用户 2026-09-24）：中间过程不再平铺成一长串，而是被**分隔物**切成 —— 分隔物除了模型输出的正文（也就是轮次标题里计入「消息」的那几段），还有用户 2026-09-25 / 09-26 规定**单独展示**的四类：**提问、引导、压缩，以及 package 工具档案里标了 `solo` 的工具卡（例：`ask_user_question` 的卡片标题显示成「提问」）**（它们同样平铺在组之间、不进折叠块，也不跟着正文发灰；轮次标题仍把这类卡算进「工具调用」）；切分成 `组1 / 消息1 / 组2 / 消息2 / 组3`，正文本身平铺在组之间、不进折叠块；组标题与轮次标题同格式但只算本组数量（轮次标题仍是全轮总数），中间过程组**一律默认折叠（包括正在生成的那一组）**，手动开合过的记住；**手动折叠轮次标题或某个组，会把它下面的组与卡片一并折叠**（再展开不恢复）；live 区跟随同一形态，正在长的那张卡片只是内容实时更新，样式与开合都不特殊；**夹在组之间的「消息」字号、行高与左右位置与最终输出相同，但默认颜色更浅一档（**中性黑灰** `--intermediate-text` = `#595959`，深色主题 `#a4a4a4`；用户 2026-09-25 明确要求不要用带蓝调的 `--muted`），且轮次分组正文的顶层不画时间轴 —— 圆点与竖线只出现在展开的中间过程组内部**；**引导送达的用户消息自己也是一个折叠块**（默认折叠）：折叠态只有一行「引导 · 用户输入的文本」（多余的部分显示省略号），展开后沿用原来的展示（右对齐气泡 + 下方状态行）；**正在生成的中间过程也住在这条时间轴上**（用户 2026-09-25）：实时区与历史区的分界改成「这一轮是否结束」——还在进行的那一整轮（连同已经落定的思考与工具卡）与正在流式的输出由实时区一次渲染成同一个折叠块，轮次标题的计数因此实时更新，本轮结束后整轮移交回历史区且折叠状态不跳；最终输出仍在折叠块外；轮次分组在进行中保持展开、**本轮一结束就自动折叠**（不再等下一个用户输入开始），只要手动点过轮次标题就不再自动折叠。思考块与工具卡默认折叠，**开始与完成都不会改变它们的开合**。
- 思考、工具、通知与「其他」条目的折叠标题统一使用垂直居中的类型图标；hover 时显示紧凑的实心向右三角，展开后显示实心向下三角并隐藏标题后的 `·`。
- 扩展写进会话的旁路条目（Pi 的 `custom` Entry，**页面统一叫「其他」**）分两种：**夹在本轮过程之间**的（如一次搜索的结果）归进当前中间过程组、**不再把会话切开**；**孤立的一条**（调度器心跳、面板状态）仍像通知那样逐条平铺。卡片标题保留各家的 `customType` 原名，归组的这些在轮次与组标题里以「其他`n`」计数（**排在最后**），全部类型一律保留显示。
- 第三方 package 的工具在会话里怎么显示，由**包目录下的 `tool-profile.js`** 声明、`web/packages/tool-profiles.js` 统一登记，通用组件只查表：`ask_user_question` 的卡片标题显示「**提问**」并标了 `solo` —— 单独平铺、不折进中间过程组，但轮次标题仍把它算进「工具调用」。**折叠态摘要显示第一题的 `header`**（多题显示「`header` 等 N 题」，缺 `header` 退回题干前 16 字 + `…`），答完也不换成答案；卡片与活动栏 tab 都用它的**专属图标 `ask-question`**（定义同样在包目录里，通用图标表只登记与渲染）
- Web 提交普通 prompt 时立即清空输入框，明确发送失败且用户尚未输入新内容时恢复草稿。会话空闲时会在浏览器同一交互帧显示用户消息卡，后端临时消息或真实会话记录到达后自动替换且不重复；会话正在运行时，新 Prompt 只进入 Follow-up 队列，不会提前或残留在主会话，轮到它实际执行后才显示为用户消息。提示词模板与技能命令也会跟踪各自的模型轮次。模型超过 1 秒尚未开始响应时显示 `正在等待模型响应... (Ns)`，收到首个响应事件、轮次失败或取消后立即移除。
- 普通 Prompt action 会等待 Pi 完成发送 preflight 后再解除浏览器提交状态；连续快速输入时，第一条启动当前轮，后续消息可靠进入 Follow-up，不会并发调用底层 agent。
- 输入卡上方的活动组件栏统一承载扩展交互请求与消息队列，以 tab 切换并在折叠后保留表单草稿；tab 标题支持 inline Markdown（行内代码徽片、粗体等，经 DOMPurify 行内白名单清洗且属性全清），消息队列 tab 因此显示为「消息队列 3」且数量是徽片；排序、自动展开、阻塞、键盘、布局及新活动接入规范见 [`docs/activity-components.md`](docs/activity-components.md)。输入的 Prompt 默认进入 Follow-up 排队；队列总数非零时展开态大框顶部显示“消息队列”tab（折叠态则是一条一个长条），面板内始终按上方引导队列、下方排队队列展示两个分组，标题、数量和说明各自合并为单行，空分组显示“暂无”，引导队列使用浅色背景。新增、编辑或转换队列消息时**不再自动展开面板**（只在面板开着时让具体消息边框闪烁两次）；折叠态里队列是**一条消息一个长条**（引导在前、排队在后，最多 5 条，剩下的收进「还有 N 条」），长条最左按类型用不同图标（引导 `send`／排队 `mode`）并带当前类型徽片「引导」或「排队」，右侧直接带「改为引导 / 改为排队」与「删除」两个按钮；删除和 Pi 正常消费不触发。队列项可在两类间转换、就地编辑或单条删除，文字与图片会一起保留；编辑器支持展示、预览、选择、粘贴、拖入和移除图片，也允许纯图片队列项。面板不提供重复的标题和输入区。所有更新以 revision 校验防止模型消费队列时误改，并返回操作前后完整条目。以**引导**方式送达的消息不会新开一轮：它归入被它插话的那一轮（渲染在原消息流程的折叠块内），并在轮次标题**末尾之前**（流程计数之后、「压缩」之前）计入「引导`1`」；展开后它自己的状态行还会在时间后标出「· 引导」（如 `16:17 · 引导`）：Pi 落盘的用户消息不带来源标记，所以该项由队列观察推定并随会话状态落盘，**只能覆盖扩展加载之后的消息**，更早的历史不猜测。Pi 系统、RPC、扩展和 Web 队列 API 见 [`docs/pi-prompt-queue-api.md`](docs/pi-prompt-queue-api.md)。
- pi-atom-web 在 Pi 正式扩展 API 之上补出的队列、UI 对话、自定义 Entry、第三方 package、工具事件、历史窗口和 Web 派生状态接口统一称为“兼容层 API”；接口边界、降级策略与版本依赖见 [`extensions/COMPATIBILITY-API.md`](extensions/COMPATIBILITY-API.md)。
- 输入框左下角是一个**加号**按钮，点开添加菜单可选**添加图片 / 斜杠命令 / 附加技能 / 压缩上下文**（展开时加号旋转成 ×；后三项只把命令写进草稿并聚焦，发送仍由你按下；图片也可直接拖入浏览器或直接粘贴到输入框）；提交前显示可预览、可移除的方形缩略图，允许只发送图片或与文字组成同一条消息。发送后，多张图片以 80px 方形附件条右对齐显示在用户文字气泡上方。输入框附件、队列附件和会话图片均可点击打开全屏等比例预览，并支持关闭按钮、点击遮罩或 `Esc` 关闭。Web 不额外限制图片数量、单张大小或合计大小，实际支持范围由 Pi、当前模型与 provider 决定。
- 输入框右下角只有**一个**模型与思考级别按钮：显示当前模型名与当前级别的仪表图（点亮的刻度段与指针角度就是级别本身）。点开是一个面板：顶部是当前模型名，点它进入「供应方 + 模型」两栏选择（左上角可返回，`/model` 直接落在这一页）；中间显示当前「[图标] 思考级别 · xxx」；底部滑块按该模型实际支持的级别分档，拖动即生效、面板不关。忙碌/处理中同样可以切：这时的选择先缓在浏览器里，按钮与面板用待生效色标出，本轮结束后自动补发。
- 网页发送的斜杠命令显示为命令记录；命令横线（连同模型/思考级别切换与已中断提示）与其它顶层条目一样放在各自的 `<article class="message">` 里，共用同一条 8px 间距节奏。`/compact` 另带执行状态：压缩期间在命令横线下方显示「正在压缩上下文...（x秒）」并实时计时（hover 在上方弹开始时间；同时底部不再重复一条压缩状态），压缩结束后 branch 里的压缩条目渲染为「压缩」可折叠块（折叠摘要 `从150,722个token中压缩`，展开是压缩摘要全文 Markdown），**手动压缩不属于任何一轮的中间过程**（用户 2026-09-23 明确）：它是用户显式按下的页面边界，像命令记录一样单独渲染（不钻进轮次折叠块、不计入轮次标题），完成行「压缩完成（耗时2分钟48秒）」（hover 弹开始/结束时间与总耗时）跟在折叠块下方**。运行中的压缩状态不落盘，中途退出或刷新不会残留转不完的计时。**自动压缩（上下文阈值 / 溢出恢复，没有 `/compact` 命令记录）才算本轮的一步**：它不切断轮次，而是归入所在轮的折叠块并在标题**末尾**计入「压缩`1`」，同时把耗时挂在块自己身上：扩展按压缩条目 id 记下起止时间并落盘（刷新后仍在），折叠块标题右侧显示耗时，形态与思考 / 工具调用**完全一致**（折叠到秒、不足一秒 `<1s`、展开到毫秒，没有 hover 弹层）；手动 `/compact` 维持原样，只有块下方那行完成行。服务运行及 `/reload` 替换实例初始化期间的 `ctx.ui.notify()` 同步为 TUI 通知（如 `/wj-status`），保留终端输出。展示记录按会话与分支隔离，项目级保留最近 500 条且不进入模型上下文；只有包含随机凭证的 Web 连接地址不会镜像。
- 所有插件通过 `pi.appendEntry(customType, data)` 写入的自定义会话 Entry 都会转发到 Web，无需为插件逐个适配。后端调用 Pi 当前注册的 TUI renderer 生成折叠态和展开态文本并清除 ANSI 控制码；Web 通用卡片优先显示该文本，展开正文使用与 TUI 通知相同的默认字体，原始 JSON 收在“原始数据”二级折叠区。renderer 不存在或执行失败时，可识别的对象数据按 JSON 代码块展示并以 `[JSON OBJECT]` 作为摘要，其他值按纯文本展示；TUI 组件本身不会在浏览器执行。
- Thinking、工具调用、TUI 通知和自定义 Entry 共用统一的折叠基座：没有外框与底色，标题统一灰色、形如「图标 + 类型 · 标题」，**展开后的中间过程组内部是一条时间轴：组内内容右移一档，每个思考卡 / 工具卡左侧各坐一个浅色小圆点，圆点下方一段竖线（点到线之间断开，条目之间也断开）；轮次分组正文的顶层条目（中间过程组标题、平铺的「消息」、单独展示的引导块与压缩块）不画圆点与竖线，与轮次标题和最终输出左缘齐平**，工具调用的状态色遵循「正常灰／警告橙／报错红」，报错时整行（含图标、标题与单行摘要）标红；折叠时悬停图标会变成实心向右三角，展开时是实心向下三角。通用工具直接展示 JSON Input 与无内框的 Markdown Output，背景与主会话一致，Output 内代码块完整显示且不产生纵向滚动条。所有折叠摘要把连续空白和换行压成单个空格，只显示一行并在溢出时显示省略号；通知与自定义 Entry 默认折叠，展开后显示完整通知正文或结构化数据。
- 发送消息默认使用追加（followUp）模式；composer 使用顶部略宽、其余方向紧凑的 padding，prompt 不叠加上下 padding，默认显示 2 行并自动增高至最多 10 行且不超过会话区可用高度，操作栏高度与 32px 圆形发送按钮匹配。发送 SVG 精确居中，hover/active 保持强调色。提交与停止**共用同一个按钮位**：空闲显示提交，正在执行且输入为空时由停止按钮顶掉提交，正在执行但已输入内容（只贴图、文字为空也算）时又换回提交（点击即排队），同一时刻不会并排出现两个按钮；停止按钮与发送按钮同尺寸同圆形，平时浅红底加细描边、悬停填满实心红。输入框右侧以无图标文本按钮打开模型选择器，按供应方筛选真实可用模型并搜索；相邻按钮独立选择思考级别，并只列出当前模型实际支持的级别。当前模型、供应方和思考等级会默认选中；供应方筛选切换后保持当前选择，“显示全部”按供应方名称分组模型，右侧标题和搜索框固定、仅下方模型列表滚动；无当前模型时，单一供应方自动选中，多个供应方保持显示全部。底部 Token 输入/输出使用尺寸与形状完全对称的 SVG 箭头。
- 回车的语义按设备分流：**桌面端** Enter 发送、Shift+Enter 换行；**手机端（触屏，`pointer:coarse`）** Enter 与输入法的回车一律当换行，**发送只能点发送按钮**（把桌面窗口拖窄不会改变键盘行为）。
- 输入 `/` 提示当前 pi 的扩展命令、提示词模板、`/skill:…` 与 Web 命令；按前缀筛选，↑/↓ 选择，Tab/Enter 或点击补全，添加参数后发送；Esc 关闭提示。Web 支持 `/reload`、`/model`、`/session`、`/copy`、`/name <名称>` 和 `/compact [指令]`；其余已知命令通过 pi 原生命令分发与模板展开执行。
- 当前会话名称、目录、模型与思考等级；未设置标题时显示“未命名会话”（标题行可直接重命名）；明暗主题可在设置页切换（含跟随系统）；自动重连。浮动输入框右侧以「上下文占比环 · `模型` · `思考等级`」展示当前状态：环按占用比例从 12 点顺时针填充，超过 60% 转橙、超过 85% 转红，点击可看当前上下文、最大上下文与占比并一键压缩（刚压缩完、暂无用量时只画底图）；输入区、状态栏和信息卡统一使用内联 SVG 图标。下方状态栏由 `.status-shell` 提供稍宽松且上下相等的间距，按钮、文字与 SVG 使用统一行盒并完整垂直居中，汇总会话标题、对话/轨迹、平均输出速度（只算模型生成正文与思考的那段过程，不含空闲、工具执行与压缩；生成中则把当前这条消息一并算进同一个均值，尚未观测时显示 `—`）、Token、缓存命中率与成本，只更新数值文本而不重建按钮，保证 hover 稳定。宽度不够时按固定顺序逐级收紧（量实际宽度，能放下就不提前隐）：会话名先固定显示为「会话」→ 隐总计 Token → 隐轨迹事件数 → 隐输入/输出 Token、但把「总计」放回来（那时用量按钮只剩这一个数字）→ 隐对话轮数 → 隐成本（`$x.xx`）；被隐掉的数值仍然点对应按钮就能在弹层里看全。窄屏也不再为「挤不下就横向滚动」把状态栏改成左对齐（那条 `justify-content:flex-start` 会让压缩后的短内容整条偏左），始终居中；点击会话标题展示会话 ID、会话文件路径、所属工作区及路径、活跃与创建时间、活跃时长，其他分组也可查看并复制详细值。左下角提供相同的会话信息卡。信息卡点击触发按钮或卡片以外的任意位置关闭。
- **长期挂在后台也不会停在旧进度**：服务端每 15 秒发一次 SSE 心跳，客户端对「多久没收到字节」设了看门狗，半开连接（机器休眠、网络切换后既不报错也不来数据）会被主动拆掉并**立刻**重连取新快照，不等指数退避；标签页切回前台时还会立刻应用后台合并好的最后一次更新，并在原本贴着底部时补一次滚底。
- TUI 切换会话后同步网页，并拒绝携带旧会话 ID 的操作；未发送草稿按会话保留在页面内存。

## 边界

这是结构化会话界面，不是终端画面的镜像。尚未适配的内置终端命令（如 `/settings`）、自定义 TUI widget 仍在终端使用；扩展交互请求见下方通用支持说明；图片目前显示占位提示。网页发送使用 pi 的用户消息 API；仅对当前命令列表中的斜杠命令启用命令分发，未知命令报错，不作为普通消息交给模型。命令接收成功表示已交给 pi，通过 `notify` 输出的命令结果会同步网页；其他错误展示方式仍在 TUI 显示，标准交互弹窗通过扩展请求桥接。网页不直接执行终端 shell 命令。已有生成在扩展首次加载之前开始时，网页会在后续消息事件或完成后更新。

服务默认只监听 `127.0.0.1`，每次启动生成随机凭证（想长期收藏地址可在「设置 → 会话 → Web 服务」打开**固定凭证**：凭证 = `sha256(本机密钥 + 会话 id)`，同一个会话任何时候的地址都一样；代价是泄露出去的地址在换密钥前一直有效）；`/web-wlan` 改为监听 `0.0.0.0`（见上文）。固定端口由一个独立的 Web UI 网关进程持有（本机 31359 / 局域网 31360，在「设置 → 会话 → Web 服务」可改），各 pi 进程仍只听 127.0.0.1 的随机私有端口、由网关按 `/<会话短码>/` 转发，所以固定端口不改变原有信任边界：凭证仍由 URL fragment 传入并存入当前标签页的 sessionStorage，API 校验凭证与会话；回环网关与回环服务校验 Host 和 Origin，局域网模式按约定跳过 Host/Origin 校验（凭证是唯一凭据）。网页不加载远程脚本，Markdown 经 DOMPurify 清洗，远程图片不自动加载。完整打开链接相当于当前会话的操作凭证。「自动恢复」开着时，上次用 `/web-wlan` 开过的会话重启 pi 后会照原样恢复成 `0.0.0.0` 监听（唯一的凭据仍只剩 URL 片段里的凭证）；不想这样请用「设置 → 会话 → Web 服务 → 自动恢复」关掉或 `/web auto off`（只影响下次启动）。

Pi 会话文件未记录的 Web 派生状态保存在当前工作区 `.pi/atom/<sessionId>/web-state.json`：Thinking 与工具的最终耗时、用户手动折叠状态，以及 Web 镜像的命令和通知。文件采用版本化 JSON 和同目录原子替换，损坏或版本不支持时安全回退为空状态。随机连接凭证、临时 Prompt、运行中的工具和界面滚动位置不会写盘。跨项目设置统一预留在 `~/.pi/atom/`：Web 网关占它的 `web/` 子目录，里面是端口配置 `config.json` 与各端口的注册密钥 `gateway-<端口>.key`（都只在开了 Web 之后才会创建）。

不创建额外 pi 进程，不直接读写会话文件，不生成运行时数据文件，也不修改全局配置。主题偏好仅保存在浏览器中。

## 开发验证

前端使用 Vue 3 Composition API 的普通 JavaScript `h()` 组件、Pinia 和 Vue Router memory history。浏览器直接加载本地 ESM，不需要构建或模板编译；Vue runtime、Pinia、Router 及 devtools API 均通过 HTTP 白名单提供。固定 import map 使用 CSP SHA-256 校验，不开放外部 CDN、`unsafe-inline` 或 `unsafe-eval`。

`shared/protocol.js` 由扩展与浏览器共同使用，校验版本、动作和事件结构。SSE 首次连接发送快照，后续按字段发送增量并附带流标识、序号和会话 ID；实时消息更新不携带完整历史。工具运行事件经 `extensions/tool-events.ts` 转为有界、可序列化的数据，工具私有对象不会破坏事件流；无法编码的单条事件会被跳过且不消耗 SSE 序号。浏览器将历史列表和实时列表分为独立组件，按稳定消息 ID 保持节点与 Thinking 手动状态。断线、卸载和重载会取消连接、请求及重试任务。

```bash
npm run test:browser
```

项目约定分两层：`AGENTS.md` 只放硬约束、待办与索引，`DETAILS.md` 收录按主题分节的详细约定（含实测数值与踩坑依据）；改动细节写进 `DETAILS.md` 对应小节，只有普适红线进 `AGENTS.md`。

`check` 递归检查扩展、共享协议和所有浏览器模块；`test` 在没有测试文件时失败。浏览器测试独立运行，通过内存快照和模拟动作驱动真实本地 HTTP 服务，不调用模型、不读写真实会话。当前 Windows 默认使用已安装的 Microsoft Edge；其他系统可设置 `PLAYWRIGHT_CHANNEL=chromium` 并先执行 `npx playwright install chromium`。

`extensions/index.ts` 负责 pi 生命周期和会话桥接；`extensions/server.ts` 提供 HTTP/SSE；`web/main.js` 启动应用，`web/api/` 管理传输，`web/stores/` 管理状态，`web/components/` 与 `web/views/` 负责 UI。Marked、DOMPurify、highlight.js 与 xterm.js 均通过本地 HTTP 路径提供，正常使用无需 CDN；上下文页、设置页和 xterm 只在首次使用时按需加载。

### 重载与入口缓存

扩展使用 `.ts` 入口和服务模块，避免当前 pi 加载器对原生 ESM `.js` 的缓存导致 `/reload` 后继续运行旧代码。由旧版升级后执行 `/reload` 再 `/web`，扩展清单会加载新的 `.ts` 路径。

## 工作区侧栏

对话工具栏可打开通用工作区侧栏。桌面端侧栏与对话并列，拖动分隔线可调整宽度，宽度保存在浏览器 `localStorage`；小屏下侧栏覆盖页面。侧栏内容由懒加载注册表管理，当前登记「工作区」容器，容器内提供**文件**与 **Git** 两种功能视图：文件视图包含目录树、搜索、单文件快捷预览、顶部可关闭的目录/文件标签、文本查看与编辑、自动换行开关（标题栏图标，默认关、全局记住，开启后行号逐行对齐）、文件操作；Git 视图包含变更、差异、历史、冲突处理和常用写操作。两种视图切换显示，不会同时组成文件树、编辑器、Git 三栏。文本文件超过 2 MiB 时只读分页，下载上限 64 MiB；未保存草稿暂存在页面内存。终端浏览器尚未实现，也未登记为侧栏内容。

## 通用扩展请求

按 pi UI 接口统一桥接，无需为 `/piolium-help` 等命令编写专用适配：

- `select`、`confirm`、`input`：网页显示选择、确认或输入控件，支持取消；网页与 TUI 任意一端完成后关闭请求，返回原始选项值。
- `custom`：使用本地 xterm.js 镜像同一个 TUI 组件的渲染行，保留 ANSI SGR 颜色、背景与选中样式；按终端列宽等比缩放到网页面板，避免横线折行。点击面板后直接输入，支持方向键、Tab、退格、Ctrl/Alt 组合键、中文与粘贴；按顺序转发输入并在更新后保留焦点。不创建第二个组件实例，像素图片/终端私有图形协议不转换。
- `editor`：显示标题和预填内容，提示在 TUI 完成。当前宿主接口不支持外部提交/取消，不能安全地从 Web 接管。
- 请求以 ID 和会话 ID 校验，重连时重发仍在等待的请求；收起保留等待，取消才结束请求。服务停止恢复原 UI 方法。

设计参考 [pi-atom-console 的扩展 UI 通道](https://github.com/WJBFks/pi-atom-console/blob/main/lib/rpc-manager.ts)，但本扩展保留并桥接宿主 TUI。

输入框作为 dock 浮动固定在对话区底部，问卷与通用扩展请求固定显示在输入框正上方，三者与对话同宽。页面不显示产品顶部标题栏和左侧会话栏，对话区占满整个视口；对话工具栏保持固定，其下方消息区使用完整高度纵向滚动条。只有消息区位于最底部时才自动跟随新内容，用户向上滚动任意距离后立即暂停，重新滚到底部后恢复；离底时在输入框上方居中显示圆形向下按钮，点击即可回到最新消息。对话消息、输入框与底部状态栏共用同一条居中列，默认 860px；鼠标移到内容区左右边界时会在鼠标高度出现一条两端渐隐的细线手柄，拖动可对称调整这条列的宽度，双击手柄恢复默认，键盘聚焦后也可用 ←/→ 调整，宽度记在浏览器本地，窄视口不提供。页面按 dock 实际高度为消息增加底部留白，使最后一条消息可以滚动到浮层上方。长问卷仅滚动卡片内容区，长通用扩展请求滚动请求面板，输入框始终可见。会话详情、工作区、模型、思考等级和统计仍可从底部状态栏查看。

跳到最新消息时会先恢复自动跟随，并在当前界面更新和下一渲染帧再次校准到底部；快速增长的 Thinking 或工具输出不会超过这次跳转。

终端画面仅允许 SGR 样式控制，屏蔽 OSC 链接、剪贴板命令及其他终端控制。面板仍只有外层滚动条；TUI 很宽时等比缩放会使文字变小，可缩窄原终端改善阅读。

## ask_user_question 专用适配

已检查并实测本机 `@juicesharp/rpiv-ask-user-question` **2.9.0** 的参数、公开事件和结果协议。该工具始终优先使用结构化问卷，不解析终端画面或模拟方向键来填写。

| 原扩展能力                  | Web 表现与返回语义                                                                                                                                                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1–4 个问题，每题 2–4 个选项 | 顶栏显示原始 question.header（单题同样保留），并提供分页、上一题/下一题和核对页；保留 question/label/description                                                                          |
| 单选                        | 原生 radio；返回 `kind: option` 和选项原始 label                                                                                                                                          |
| 多选                        | 原生 checkbox；`selected` 按原选项顺序排列并返回 `kind: multi`；勾选与自由文本是**两个独立存储**，互不清空、可共存（提交时文本作为额外 `selected` 项）；取消自由文本行的勾选只取消选中，文本仍保留                                                                        |
| 自由填写（所有题型）        | 多行文本框；无勾选项时返回 `kind: custom` 并替代普通选项；多选下已有勾选时文本作为额外 `selected` 项，且不清空勾选；空文本按原协议返回 null                                                             |
| 备注                        | 每题独立多行备注，附在对应答案的 notes；备注不把未答题变成已答                                                                                                                            |
| 全局备注                    | 多题核对页提供整个问卷的多行备注；可单独提交，取消时也按 2.9.0 契约保留在 `details.globalNote`                                                                                              |
| 单选 preview                | 选择区与预览区共用统一外框；使用紧贴选项的低高度折叠条，展开后安全渲染 Markdown/代码，支持逐项对比；按契约保留单个换行（GFM 硬换行）与行首缩进（`white-space:pre-wrap`），ASCII 布局不会被折叠或压平；表单重绘保留每项展开状态；选中后原始 preview 随答案返回；多选与自由回答不携带 preview |
| 多题核对与修改              | 核对页列出答案、备注、未答项，可返回修改；答案按行展示：勾选项依次编号 `1.` `2.`…，自定义输入标 `X.`；「修改」为紧凑小按钮，位于每题标题行右侧；允许显式提交部分答案；全未答由原工具按其既有逻辑判为未回答 |
| 取消                        | 返回 `{answers, cancelled:true}`，保留已填的有效部分；不返回 undefined，以免误触发原工具的 RPC 降级逻辑                                                                                   |
| 收起/恢复                   | 收起只隐藏表单，不提交或取消；草稿保留                                                                                                                                                    |
| 刷新/重连                   | 同一请求在本标签页 sessionStorage 恢复草稿；请求结束后清理，新请求独立                                                                                                                    |
| TUI 作答                    | TUI 仍可完成问卷；任意一端最终提交/取消后，另一端的请求关闭，迟到回应被拒绝                                                                                                               |

网页与 TUI 的**未提交草稿独立**，不会逐键同步；最终先完成的一端生效。浏览器使用多行文本框完成编辑，TUI 的 Ctrl+G 外部编辑器与终端快捷键配置仍由原扩展负责。多语言题目原文保留，网页控件使用中文。

兼容代码按 package 隔离在 `extensions/packages/@juicesharp/rpiv-ask-user-question/` 和 `web/packages/@juicesharp/rpiv-ask-user-question/`。后端只在观察到该扩展唯一的 `rpiv:ask-user:prompt` 公开事件后动态加载适配器；Web 只在收到对应 `packageId` 请求后动态加载 Vue 表单和专用 CSS。未安装或未触发时不加载、不生效、不报错、不警告。适配器关联真实工具参数（含 preview）与公开事件，再匹配当前 2.9.0 的间接 `Session` 工厂或旧版 `QuestionnaireSession` 工厂；通用 `dialogs.ts` 只处理 package claim，不包含问卷业务规则。适配器还会先用宿主问卷 schema 上限（1–4 题、每题 2–4 选项、header ≤16、label ≤60）校验工具调用，不合契约就不认领、静默回退通用终端；Web 端渲染前用包内 `sanitizeQuestions()` 再裁一次。字段级 schema 一律留在包模块，`shared/protocol.ts/js` 只做通用有界校验（JSON 可序列化 + 总长度），不含任何 package 专属字段名。无需修改或打补丁到被适配扩展。

必须先启动 `/web` 再触发新问卷；已打开的旧 TUI 问卷不会被事后接管。若未来扩展更改工厂/协议而未匹配，保留原 custom 兜底，不把其他扩展的请求错认成问卷。

专用问卷采用紧凑独立卡片，普通选项纵向排列；自由回答作为最后一张同款选项卡，仅显示随题型变化的选择框和带 placeholder 的输入框：单选题使用 radio，聚焦或输入会选中自由回答并取消普通选项；多选题使用 checkbox，勾选与自由文本是两个独立存储：勾选/取消勾选不清空文本，输入文本不清空勾选，取消自由文本行的勾选也不删除已输入内容；自由文本行自身的勾选态独立于其它选项。备注仍按需展开，说明同样使用 placeholder。“清除选择”和“取消问卷”集中在底部操作栏，与导航和提交按钮排列在一起。单题作答后可直接提交，多题保留核对页；问卷固定在输入框上方并随内容增高，达到可用高度后仅滚动问卷内容区。选项、页签和表单按钮引起局部重绘时保留当前滚动位置。
